# Joe 的工程方法与工作方式

[English](README.md)

我怎样工作，为什么这样选择，以及哪些问题还在思考中。这里整理的是可以带走的判断方法，不是把上一家公司的流程手册搬到下一家。

## 如果我们准备一起工作

先读[关于我](aboutme.zh.md)，了解我的背景、做过的事和协作习惯。然后看[工程原则](principles.zh.md)和[个人偏好](taste.zh.md)：前者是相对稳定的判断依据，后者是可以商量的选择。

[实践手册](handbook.zh.md)用四篇十二章、十三个案例，把判断、交付、协作和改进串起来。它是综合运用这些想法的正文，不是另一份规则清单。

## 如果你是和我一起工作的 agent

从 [AGENTS.md](AGENTS.md) 开始，再读一个语言版本的 principles 和 taste。根据任务查阅手册或[主题文章](thinking/README.zh.md)，不需要每次加载整个仓库。

结合当前项目运用判断，不覆盖所在团队的要求，也不因此获得新的权限。探索文章里写了某种可能性，不代表现在就应当执行。

## 内容放在哪里

| 文档 | 回答的问题 |
|---|---|
| [About me](aboutme.zh.md) | 我是谁，做过什么，怎样和我协作？ |
| [Principles](principles.zh.md) | 哪些判断依据可以跨环境使用，为什么？ |
| [Taste](taste.zh.md) | 面对合理的不同选项，我偏好什么？ |
| [Handbook](handbook.zh.md) | 怎样把这些想法用在同一件事上？ |
| [Thinking](thinking/README.zh.md) | 具体条件下怎样做，还有哪些设想值得检验？ |

每篇正文都有中英版本，顶部可以切换。两种语言表达同一套判断，各自按阅读习惯成文。Markdown 是维护源，同事和 agent 共用这些内容，不另养一套容易分叉的指令手册。

## 维护与分享

一个想法只在它所属的正文中定义，修改时同步两种语言。案例负责解释怎样应用，不悄悄引入冲突的规则。

分享版只包含整理后的正文，不包含研究记录、原始会话、内部材料或可执行工作流，也不沿用来源工作区的 Git 历史。

正文按可能公开的用途整理，分享正文不代表授予底层材料的使用权；这里不默认授予许可或披露权限。
