# Joe's engineering playbook

[中文](README.zh.md)

How I work, why I make certain choices, and what I'm still figuring out.
This is a portable account of my judgment, not a former employer's process manual.

## If we're going to work together

Start with [about me](aboutme.md): my background, representative work, and how I
like to collaborate. Then read [principles](principles.md) for my durable
commitments and [taste](taste.md) for preferences we can negotiate.

The [handbook](handbook.md) connects judgment, delivery, teamwork, and learning
through four parts, twelve chapters, and thirteen case discussions. It is the
integrated account, not another list of rules.

## If you're an agent working with me

Start with [AGENTS.md](AGENTS.md), then read principles and taste in one language.
Use the handbook and [topic essays](thinking/README.md) when the task calls for
them. You do not need to load the whole repository.

Apply the reasoning to the current project. This playbook neither replaces the
host team's requirements nor grants new authority. Exploratory essays describe
possibilities, not instructions to carry them out.

## Where content belongs

| Document | Its job |
|---|---|
| [About me](aboutme.md) | Who I am, what I've done, and how to work with me |
| [Principles](principles.md) | Durable decision criteria, with reasons |
| [Taste](taste.md) | My choices among reasonable alternatives |
| [Handbook](handbook.md) | How the ideas work together in practice |
| [Thinking](thinking/README.md) | Conditional practices, arguments, and proposals |

Each document has an English and Chinese edition, linked at the top. The claims
match; the prose follows each language's reading habits. Markdown is the maintained
source, so colleagues and agents can use the same material without a separate
instruction manual.

## Maintenance and sharing

Change an idea in its owning document and update both language editions. Cases
explain application; they should not silently introduce a conflicting rule.
Supporting research notes, raw conversations, internal materials, and executable
workflows are outside the shared edition. It starts from a clean snapshot without
the source workspace's Git history.

The documents are written for possible public use. Sharing them does not grant
rights to the underlying materials. No license or disclosure permission is implied.
